# Connecting the real systems

The concept runs end to end without any Avivi system. This file lists every piece that is mocked or example data today, and how to connect the production system. Most connections are an environment variable (see `.env.example`); the rest are small, isolated changes in the files named below.

| Area | Today (demo) | Production |
|---|---|---|
| CRM and lead routing | `/api/lead` stores leads in memory and on the device | Webhook to the CRM, durable store |
| Showroom calendars | Example slots | Live availability per showroom, appointment created on confirm |
| Showroom details | Addresses and hours labelled “to confirm” / “example” | Confirmed data |
| WhatsApp | `wa.me` links with prefilled text, example number | Avivi’s WhatsApp Business number and template messages |
| Avivi Smart & Simple app | Phone mockup, store badges as placeholders | Store links, deep link from the booking confirmation |
| Products site | Curated example selection, link to avivi.com | Product feed and canonical products-site URL |
| AI visualiser | Pre-rendered rooms per collection | Image API key |
| Avivi Designer | 21 scripted, grounded topics in four languages | Claude (or OpenAI) API key |
| Analytics | Events kept in the session after consent | GA4 (or another tool) after consent |
| Showroom inbox | Demo password, example pipeline | Real password or SSO, live leads (or the CRM itself) |
| Content and imagery | Concept renders, photography slots, demo articles | Avivi photography, confirmed copy, optional CMS |

## 1. CRM and lead routing

Every form on the site (booking, architect project, contractor inquiry, developer kitchen, service request, contact, style finder result, designer callback) calls `submitLead()` in `lib/leads.ts`, which posts to `/api/lead` (`app/api/lead/route.ts`). The route validates the data, then:

- forwards it to `LEAD_WEBHOOK_URL` (`lib/server/leads.ts`), and
- stores it in Upstash Redis / Vercel KV when `UPSTASH_REDIS_REST_*` or `KV_REST_API_*` are set (memory otherwise).

Payload (JSON, POST):

```json
{
  "source": "avivi-concept",
  "ref": "AV-7Q4K-0211",
  "type": "booking",
  "createdAt": 1793600000000,
  "status": "new",
  "payload": {
    "locale": "he",
    "name": "…",
    "phone": "…",
    "email": "…",
    "city": "…",
    "branch": "herzliya",
    "project": "renovation",
    "date": "2026-11-03",
    "time": "10:00",
    "notes": "…",
    "attachments": {
      "visualisations": [{ "room": "b", "collection": "dark" }],
      "plans": [{ "code": "…", "summary": { "shape": "L", "width": 400, "depth": 380, "collection": "modern" } }],
      "style": { "collection": "light", "brief": ["…"] },
      "products": ["marble-white"]
    },
    "extra": { "interest": "dark" },
    "source": "/book"
  }
}
```

- `type` is one of `booking`, `architect`, `contractor`, `developer`, `service`, `contact`, `style`, `designer`. Route by `type` and `branch` in the CRM (Salesforce, HubSpot, Priority, Monday…) or through Make / Zapier / n8n.
- Set `LEAD_WEBHOOK_SECRET` and verify `x-avivi-signature: sha256=<HMAC-SHA256 of the raw body>` on the receiving side.
- A plan `code` opens the exact plan at `/planner?p=<code>`; designers can open it from the CRM record.
- Consent is collected on every form that asks for contact details; record it with the lead (it is enforced on the client before sending).

## 2. Showroom calendars

Slots are generated by `exampleSlots()` in `lib/data/branches.ts` and shown with the label “Example availability”. To go live:

1. Add `app/api/slots/route.ts` returning free slots for `?branch=<id>&date=<YYYY-MM-DD>`, backed by each showroom’s calendar (Google Calendar / Microsoft 365 through a scheduling service, or the CRM’s appointment API).
2. In `components/book/Booking.tsx`, replace the `exampleSlots()` call with a fetch to that route.
3. On confirmation, create the appointment from the webhook handler (step 1), so the slot is held in the same place the showroom team works.

The confirmation already provides an `.ics` file (`lib/ics.ts`, Israel time with daylight saving) and a Google Calendar link.

## 3. Showroom details

Names, regions and map positions are in `lib/data/branches.ts` and `content/*.ts` (`showrooms.branches`). Street addresses and opening hours are not in the brief and appear as “to confirm” / “example”. When confirmed, add the address to each branch, replace `hoursExample`, and remove the example labels. Google Maps and Waze links currently search for “Avivi Kitchens <city>”; switch them to the exact place IDs.

## 4. WhatsApp

Every handoff opens `wa.me/<number>` with a prefilled message (booking reminder, visualisation, designer conversation, service request). Set `NEXT_PUBLIC_WHATSAPP_NUMBER` to Avivi’s business number. For reminders that Avivi sends (rather than the customer), use the WhatsApp Business Platform (Cloud API) with approved templates, triggered by the CRM when a booking is created.

## 5. Avivi Smart & Simple app

`/app` shows a phone mockup with example screens and two store badges. Set `NEXT_PUBLIC_APP_STORE_URL` and `NEXT_PUBLIC_PLAY_STORE_URL`; the “to confirm” label disappears when both are set. This replaces the third-party QR link used today. Recommended next step: add a universal link from the booking confirmation that opens the app on the customer’s purchase, keyed by the booking reference.

## 6. Products site

`/products` shows a curated example selection (`components/products/Products.tsx`, names in `content/*.ts`) that visitors add to their brief; the brief travels with the booking. Set `NEXT_PUBLIC_PRODUCTS_URL` to the one canonical products-site URL. To show the real range, replace the item list with a feed from the products site (ids → name, image, URL) and link each item to its page.

## 7. AI visualiser

`/api/visualise` (`app/api/visualise/route.ts`, `lib/server/visualise.ts`) calls an OpenAI-compatible `images/edits` endpoint when `IMAGE_API_KEY` (or `OPENAI_API_KEY`) is set. The prompt keeps the room’s architecture and camera and applies a recipe per collection (`RECIPES`); update the recipes when the collections are confirmed. Photos are downscaled in the browser, processed in memory and never stored or logged. Without a key, uploads get a clear demo notice and the pre-rendered example rooms. Every result carries the label “AI visualisation for inspiration; the final design is done with an Avivi designer.”

## 8. Avivi Designer

`/api/designer` (`lib/server/designer.ts`) uses Claude through the official Anthropic SDK when `ANTHROPIC_API_KEY` is set (`claude-opus-5-5` by default, override with `ANTHROPIC_MODEL`), with:

- a JSON-schema structured output (reply, cards, suggestions, handoff) that the UI renders,
- low effort for chat latency,
- **server-side refusal fallbacks enabled** (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`): if a request is declined by the model’s safety classifiers, the API retries it on Anthropic’s recommended fallback model within the same call; if the whole chain declines, the visitor is offered a person instead,
- OpenAI as an alternative (`OPENAI_API_KEY`, `OPENAI_MODEL`), and the scripted demo as the final fallback on any error.

What it may say lives in `lib/designer/knowledge.ts`: the confirmed company facts, the site tools it can point to, and general kitchen-design practice. It is told never to invent prices, lead times, delivery dates, warranty terms, specifications, addresses, hours, promotions or awards. Update `FACTS` as information is confirmed (for example warranty terms or showroom hours) and the assistant will use it. Conversations are not stored by the site; a callback request sends the conversation with the lead (`type: "designer"`).

## 9. Analytics

`lib/analytics.ts` sends events only after analytics consent (cookie banner and `/cookies`). Set `NEXT_PUBLIC_GA_ID` for GA4. Events: `tool_start`, `tool_complete`, `visualisation`, `plan_saved`, `product_toggle`, `designer_ask`, `designer_voice`, `designer_card`, `designer_handoff_offer`, `designer_call`, `designer_whatsapp`, `booking_branch`, `booking_confirmed`, `booking_ics`, `booking_whatsapp`, `lead_submit`. Withdrawing consent removes analytics cookies immediately.

## 10. Showroom inbox

`/inbox` is protected by `INBOX_PASSWORD` (HMAC session cookie, `lib/server/auth.ts`). Without it, the demo password `avivi-demo` works and only example data and leads sent from the same device are shown; server-stored leads are never exposed in demo mode. In production, either keep the inbox (set `INBOX_PASSWORD`, `INBOX_SECRET` and a Redis store) or put it behind the company’s SSO (Microsoft Entra ID / Google Workspace). The cleanest long-term setup reads the same data from the CRM API, so the showroom team sees one truth.

## 11. Content and imagery

- **Copy:** `content/he.ts` (native), `en.ts`, and the machine-assisted `ru.ts` and `fr.ts`. Send the Russian and French files for professional review; then remove the machine-assisted notice (`machineAssisted` in `lib/i18n.ts`).
- **Photography:** every image slot is named in `lib/renders.ts` and carries an art-direction note. Drop Avivi photography into `public/renders` (or a CDN) under the same names, or point the slots to new files.
- **Magazine:** three demo articles in the dictionaries; move them to a CMS (Sanity, Contentful, Storyblok) if the marketing team will publish regularly.
- **Downloads:** `public/downloads` holds example swatches, a technical sheet and CAD blocks generated by `scripts/downloads`. Replace them with the catalogue files.
